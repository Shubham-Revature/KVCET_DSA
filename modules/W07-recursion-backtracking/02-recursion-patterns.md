# Recursion Patterns (The Recursion Tree)

The factorial and countdown examples we looked at in the previous lesson are examples of **Linear Recursion**—the function only calls itself *once* per step. 

To be brutally honest, using recursion for those problems is a bad idea. A simple `for` loop would be much faster and take up less memory! 

The true, unique power of recursion is only unlocked when a function calls itself **multiple times per step**. We call this **Tree Recursion**.

---

## 1. Multiple Branches

The most famous example of Tree Recursion is the **Fibonacci Sequence**. 
The sequence goes: `0, 1, 1, 2, 3, 5, 8, 13, 21...`
The mathematical rule is simple: *Every number is the sum of the two numbers before it.*

How do we write a recursive function to find the $N$th Fibonacci number? We need the function to call itself *twice* on the same line!

```python
def fib(n):
    # Base Cases (The first two numbers are 0 and 1)
    if n == 0:
        return 0
    if n == 1:
        return 1
        
    # Recursive Case (Branching into TWO paths!)
    return fib(n - 1) + fib(n - 2)
```

---

## 2. The Recursion Tree

When a function calls itself twice, the execution no longer looks like a straight line down a Call Stack. It explodes outward like the branches of a tree.

If you call `fib(4)`:
1. `fib(4)` asks for `fib(3)` and `fib(2)`. 
2. `fib(3)` asks for `fib(2)` and `fib(1)`.
3. `fib(2)` asks for `fib(1)` and `fib(0)`.

**Execution Order:** The computer cannot do both branches at the same time. It always follows the **left-most branch** all the way down to the base case, evaluates it, and then slowly works its way back up and to the right. 

---

## 3. The Exponential Time Nightmare

Tree Recursion is mathematically beautiful, but it hides a dark secret. 

Look at the tree for `fib(4)`. Notice how `fib(2)` is calculated on the left side of the tree, and then calculated *again* on the right side of the tree? The computer completely forgot the answer and does the exact same work twice!

If every function calls itself two more times, the amount of work **doubles** at every single level of the tree. 
This means the Time Complexity of our Fibonacci function is **$O(2^N)$ Exponential Time**.

This is the worst possible Time Complexity in computer science. If you run `fib(5)`, it takes 15 function calls. If you run `fib(50)`, it takes **20 billion function calls**, and your computer will freeze for hours just to find a single number.

## Try it Yourself

**Scenario:** Let's write the Fibonacci function and add a counter to see exactly how many times the function executes.

*Your Spec:*
1. Create a global `calls` variable.
2. Write the `fib(n)` function with the two base cases.
3. Increment the global `calls` variable at the top of the function.
4. Try to find the 10th Fibonacci number. Look how many calls it takes!

```python
calls = 0

def fib(n):
    global calls
    calls += 1
    
    if n == 0:
        return 0
    if n == 1:
        return 1
        
    return fib(n - 1) + fib(n - 2)

answer = fib(10)
print(f"The 10th Fibonacci number is {answer}.")
print(f"It took {calls} function calls to find it!")

assert answer == 55
```
```text
The 10th Fibonacci number is 55.
It took 177 function calls to find it!
```
*(If you change it to `fib(20)`, it takes 21,891 calls!)*

## Common Mistakes

- **Assuming Recursion is always better:** Beginners often think writing a recursive function makes them look like a "pro" developer. As you can see from the $O(2^N)$ nightmare, naïve Tree Recursion is incredibly dangerous and slow. In the real world, you should only use recursion when a problem branches out naturally (like traversing a filesystem or exploring a maze). 

**How do we fix the $O(2^N)$ problem?**
In Week 13 (Dynamic Programming), we will learn a trick called **Memoization**. We simply create a dictionary, and every time we calculate a Fibonacci number, we save it. Before calculating `fib(2)`, we check the dictionary. If it's already there, we skip the math! This instantly drops the time complexity from $O(2^N)$ back down to $O(N)$.

---

## Key Takeaway

**Tree Recursion** occurs when a function calls itself multiple times per step, branching out to solve complex, overlapping sub-problems. The classic example is the Fibonacci sequence. While Tree Recursion is powerful, it results in **$O(2^N)$ Exponential Time** because the computer redundantly recalculates the exact same branches over and over again.

---

## Quick Glossary

| Term | Meaning |
|---|---|
| **Linear Recursion** | A recursive function that only calls itself once per step. |
| **Tree Recursion** | A recursive function that calls itself two or more times per step. |
| **Recursion Tree** | A visual representation of all the branching function calls generated by Tree Recursion. |
| **$O(2^N)$ Exponential Time** | A time complexity where the operations double with each addition to the input size; disastrously slow. |
